1. HEALTH & AUTH
================================================================================

GET    /health
  Why  : Connectivity check — verifies the API base URL is reachable.
  When : Diagnostics/manual checks.

POST   /auth/login                       {email, password, device_name}
  Why  : Sign in; returns Sanctum token + user (token saved to secure storage).
  When : Login screen submit.

POST   /auth/forgot-password           {email}
  Why  : Ask server to email a password-reset link.
  When : "Forgot password?" screen submit.

POST   /auth/reset-password            {token, email, password, password_confirmation}
  Why  : Set a new password using the emailed token. (No app screen yet —
        link currently opens outside the app.)

GET    /auth/me
  Why  : Refresh the signed-in user + staff profile on session restore.
  When : App start when a saved token exists.

POST   /auth/logout
  Why  : Revoke this device's token.
  When : User taps Log out.

POST   /auth/logout-all
  Why  : Revoke tokens on all devices.

POST   /auth/change-password           {current_password, password, password_confirmation}
  Why  : Employee changes their own password (server revokes other sessions).
  When : Settings -> Security -> Change password sheet.

PUT    /profile                        {name?, phone?}
  Why  : Update own profile fields.
  When : Profile edit (if used by UI).

GET    /me/permissions
  Why  : Fetch roles+permissions to gate role-scoped endpoints/features.
  When : After login / session restore.

3. STAFF / EMPLOYEES
================================================================================

GET    /staff?search=&department_id=&branch_id=&employment_status=&page=
  Why  : Employee list (admin), team list (manager), directory.
POST   /staff                          {employee_code, first_name, last_name,
                                        email, phone, department_id,
                                        designation_id, branch_id, team_id,
                                        manager_id, joining_date,
                                        employment_status, create_login, role,
                                        password?}
  Why  : HR adds an employee. create_login:true also creates a user account;
        password generated as matainja_<random> if not supplied, stored in
        staff.initial_password (admins only).
  When : Admin -> Employees -> Add Employee.
GET    /staff/{id}
  Why  : Single employee detail (profile page).
PUT    /staff/{id}                     {staff fields..., create_login?, role?,
                                        password?}
  Why  : Edit employee; also used to create a missing login (create_login)
        or reset an employee's password (password -> updates initial_password).
DELETE /staff/{id}
  Why  : Deactivate (sets employment_status=terminated, revokes tokens).
GET    /staff/{id}/documents
  Why  : Employee's uploaded documents.
GET    /staff/{id}/assets
  Why  : Assets currently assigned to the employee.
GET    /staff/{id}/shift-assignments
  Why  : Which shift an employee is on.
POST   /staff/{id}/shift-assignments   {shift_id, effective_from, ...}  (HR/SA)
  Why  : Assign/change an employee's shift.
DELETE /shift-assignments/{id}                                            (HR/SA)
  Why  : End a shift assignment.
